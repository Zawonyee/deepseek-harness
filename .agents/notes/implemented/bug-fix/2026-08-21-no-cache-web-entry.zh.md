# Agent Note: 不缓存 Web 入口文档
Status: implemented

[English](2026-08-21-no-cache-web-entry.md) | 中文

## 问题

Web 服务器的入口文档会选择当前带 hash 的前端 bundle，并通过 index tap 接收启动清单，但此前没有明确的缓存策略。源码更新后，浏览器可能继续复用旧入口文档，让旧客户端运行时与当前 Host 事件协议配对。页面仍能打开，单向 RPC 也可能成功，但对话事件无法渲染。

## 决策

frontend-static fallback 对 `/`、`/index.html` 以及 SPA fallback 返回的入口文档统一发送 `Cache-Control: no-store`。它的包级 `tsdown.config.ts` 从 `lib/types` 生成运行时入口，因此 workspace 构建会包含该服务器的源码改动。带 hash 的资源和动态提供的客户端插件 bundle 保持现有策略。静态服务器测试会为每条入口路径断言 no-store 策略。

## 曾考虑的替代方案

**继续依赖浏览器缓存启发式规则。** 否决，因为更新敏感的入口文档需要明确的新鲜度保证；启发式缓存可能在重启后仍保留不兼容的客户端。

**对所有静态资源禁用缓存。** 否决，因为真正变化的是入口文档这个选择器，带 hash 的资源已经独立版本化，不需要同样宽泛的策略。

**增加手动 query-string 或强制刷新要求。** 否决，因为恢复依赖用户操作，也无法覆盖正常的 Web 重启或自动打开浏览器场景。

## 后果

每次 Web 导航都会重新读取体积很小的入口文档并获得当前启动清单。带 hash 的前端资源继续按现有路径缓存；已经打开的旧标签页仍需刷新一次才能获取新的入口文档。
